# Smart Downloads Classification Server

Server-side Gemini classification API for Smart Downloads. The provider key never reaches desktop clients.

## Local development

1. Copy `.env.example` to `.env.local`.
2. Set `GEMINI_API_KEY` in `.env.local`.
3. Run `dotnet run --project SmartDownloads.Server`.

Set `DEVICE_TOKEN_SECRET` to a random value containing at least 32 characters. Optionally set `REDIS_URL` for shared counters.

Endpoints:

- `GET /health`
- `POST /v1/devices/register`
- `POST /v1/classify` with a device bearer token

## Production

Build `SmartDownloads.Server/Dockerfile` from the repository root and inject secrets through a secret manager. Use HTTPS, provider billing alerts, centralized redacted logs, and Redis-compatible shared quota storage.

The root `render.yaml` creates a Render web service and a private Key Value quota service. Render prompts for `GEMINI_API_KEY`; `DEVICE_TOKEN_SECRET` is generated by Render and remains outside Git. Free instances are for testing, sleep when idle, and do not provide durable Key Value persistence. Use paid persistent instances before a stable public launch.

`.env.local` is ignored by Git and Docker. It must never be copied into a deployment image.
